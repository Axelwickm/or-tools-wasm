MathOpt - solver backend sample

Problem: solve a tiny linear model and compare how the MathOpt frontend sends it to different solver backends.

Show code 
import { MathOpt } from 'or-tools-wasm/mathopt';

const model = MathOpt.Model('basic');
const x = model.addVariable({ lowerBound: 0, upperBound: 1, name: 'x' });
const y = model.addVariable({ lowerBound: 0, upperBound: 1, name: 'y' });

model.addLinearConstraint({ upperBound: 1, terms: [
  { variable: x, coefficient: 1 },
  { variable: y, coefficient: 1 },
]});
model.maximize([
  { variable: x, coefficient: 2 },
  { variable: y, coefficient: 1 },
]);

console.log(await model.exportMps({ executor: 'worker' }));

const result = await MathOpt.solve(model, {
  executor: 'worker',
  solverType: MathOpt.SolverType.GLOP,
  timeLimitSeconds: 5,
  messageCallback: messages => console.log(messages.join('\n')),
  glop: new MathOpt.GlopParameters({
    usePreprocessing: true,
    useScaling: true,
  }),
});
const restored = await MathOpt.parseSolveResult(result.toProtoBytes(), model, { executor: 'worker' });
console.log(restored.objectiveValue, restored.variableValuesById);
// Standalone native conversion for saving a solution separately.
const savedPrimal = await MathOpt.convertSolutionProto('primalSolution', {
  variableValues: { ids: [x.id, y.id], values: [result.value(x), result.value(y)] },
  objectiveValue: result.objectiveValue!, feasibilityStatus: 'SOLUTION_STATUS_FEASIBLE',
}, model, { executor: 'worker' });
console.log(savedPrimal.bytes);
Show serialized-model solve 
// You can also supply a typed ModelProto object from another tool.
const { bytes, response } = await MathOpt.solveProto(model.encodeModelProto(), {
  executor: 'worker',
  solverType: MathOpt.SolverType.GLOP,
});
console.log(response.termination, response.solutions);
// bytes contains the native SolveResultProto for saving or importing.
Show native incremental update 
const solver = new MathOpt.ProtoIncrementalSolver(
  model.encodeModelProto(), MathOpt.SolverType.GLOP, { executor: 'worker' });
try {
  console.log((await solver.solve()).response.termination);
  const applied = await solver.update({
    variableUpdates: { upperBounds: { ids: [x.id], values: [0] } },
  });
  if (applied) console.log((await solver.solve()).response.solutions);
  // A false update leaves the native solver unusable; close and recreate it.
} finally {
  await solver.close();
}
Show SCIP lazy constraint callback 
const model = MathOpt.Model('lazy capacity');
const x = model.addBinaryVariable({ name: 'x' });
const y = model.addBinaryVariable({ name: 'y' });
model.maximize([{ variable: x, coefficient: 2 }, { variable: y, coefficient: 1 }]);

const result = await MathOpt.solve(model, {
  executor: 'worker',
  solverType: MathOpt.SolverType.GSCIP,
  callbackRegistration: {
    requestRegistration: [MathOptCallbackEventProto.CALLBACK_EVENT_MIP_SOLUTION],
    addLazyConstraints: true,
  },
  callback: data => {
    const sum = (data.primalSolutionVector?.values ?? []).reduce((a, b) => a + b, 0);
    if (sum > 1 + 1e-6) return { cuts: [{
      linearExpression: { ids: [x.id, y.id], values: [1, 1] },
      lowerBound: -Infinity, upperBound: 1, isLazy: true,
    }] };
  },
});
console.log(result.objectiveValue, result.variableValuesById);

Adapted from ortools/math_opt/samples/python/basic_example.py. The browser demo solves the same two-variable linear model with a selectable MathOpt backend. GLPK runs with a single thread.

Model

  • The model has two variables, one capacity constraint, and one linear objective.
  • Objective names and exact priorities are model metadata. Auxiliary objectives can be built and serialized; the bundled backends do not support solving them.
  • The backend selector sends the same MathOpt model to different solver backends.
  • Integer-capable backends use binary variables; LP backends use continuous variables between 0 and 1.
  • The solution table shows how the selected backend values the same small model.
  • CP-SAT and SCIP report incumbent solutions and can stop after the first one.
  • SCIP can enforce the capacity constraint lazily by returning it from a solution callback.
  • Live solver logs show native message batches as the solve runs.
  • Serialized-model solving sends protobuf bytes directly to the same backend, with the same callbacks and solve settings.
  • The native update option sets x's upper bound to zero and solves again in the same solver. The backend returns whether it supports that update.
